# README Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Create a factual, user-first `README.md` for installing, configuring,
using, building, and extending the Motorcycle Paper plugin.

**Architecture:** Use one root Markdown document with separate administrator
and developer sections. Derive commands and permissions from `plugin.yml` and
`MotorcycleCommand.java`, configuration from `config.yml`, and build details
from `pom.xml`.

**Tech Stack:** Markdown, Paper API 1.21.7, Java 21, Maven, WorldGuard 7.0.14,
SQLite.

**Spec:** `docs/superpowers/specs/2026-11-21-readme-design.md`

## Global Constraints

- Document only behavior confirmed by the current source and resource files.
- Paper API target is `1.21.7-R0.1-SNAPSHOT`; plugin API version is `1.21`.
- Java source and target version is `21`.
- WorldGuard is a soft dependency and must not be presented as mandatory for
  basic motorcycle use.
- Persisted zones use SQLite in the plugin data folder; do not suggest YAML
  storage for dynamic data.
- Do not include generated `target/` artifacts or copy the entire config file.

## Review Focus

- Command availability differs by permission: verify `motorcycle.give` versus
  `motorcycle.admin` in the command table.
- `/moto zone create` requires both selected points in the same world and a
  valid zone name; document the required order.
- WorldGuard behavior is optional at runtime; distinguish the custom flag from
  built-in zone behavior.
- Resource-pack model and sound IDs are client-side configuration; avoid
  implying the plugin supplies those assets.
- Database initialization/loading is asynchronous; document the database
  location without promising unsupported backup or migration behavior.
